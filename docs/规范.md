# 小黑字等宽 · 规范

> 状态：✅ 已决（P0）  
> 真源：本文。实现与覆盖表必须与本文同批对齐。

字体无法「实现 Unicode 标准」的全部算法（分词、规范化由渲染器和程序做）。本项目的 **符合 Unicode** 指下列可检查约束。

## 1. 码位身份

1. `cmap` 只把字形挂到该字符的官方 Unicode 标量值上。禁止把「看起来像」的字放到错误码位。
2. 已有官方码位的字符禁止改放到私用区（PUA）充数。
3. 每个 Release 写明对齐的 **Unicode 版本**（例如 16.0）。覆盖表按该版本的已分配码位统计。
4. 兼容汉字、异体选择器、CJK 扩展区：未覆盖则在表中标「未收录」，不得用近形字顶替码位。

## 2. 格子宽（终端 2:1）

终端列宽以 [UAX #11 East Asian Width](https://www.unicode.org/reports/tr11/) 为分类来源，再落到固定格子：

| UAX #11 | 本字体推进宽度 | 格子 |
|---------|----------------|------|
| W（Wide）、F（Fullwidth） | 1 em | 2 |
| Na（Narrow）、H（Halfwidth）、N（Neutral） | 0.5 em | 1 |
| A（Ambiguous） | **0.5 em** | **1** |

**Ambiguous 一律半角**（与常见 `wcwidth`、Windows Terminal、VS Code 一致）。因此：

- ASCII、盒绘 `U+2500–257F`、方块 `U+2580–259F` 必须是半角。
- 汉字、全角标点、全角拉丁必须是全角。
- 西文（JetBrains Mono）须缩放到 **恰好半个汉字宽**，不得沿用默认约 0.6 em。

构建时对每个已映射码位断言推进宽度（允许整数舍入误差 ±1 字体单位）：

- 非间距组合记号（Unicode 类别 `Mn` / `Me`）：`0`
- 其余：`0.5 em` 或 `1.0 em`

违反则构建失败。

## 3. 字形来源（Fixed 首发）

| 范围 | 来源 | 宽度 |
|------|------|------|
| 基本拉丁、拉丁扩展、希腊、西里尔、盒绘、方块元素 | JetBrains Mono（缩放后） | 半角 |
| CJK 统一汉字及扩展（已收录部分）、中文标点 | 更纱 / 思源简体 | 全角 |
| 半角/全角形式 `U+FF00–FFEF` | 按 Unicode 全角/半角身份 | 与类别一致 |

连字：首发 **Fixed 关闭连字**，避免 `!=`、`->` 占一格而打乱表格。

## 4. 字符覆盖统计表

每个构建、每个 GitHub Release **必须**附带机器生成的覆盖表，与该次字体文件同一提交/同一产物，禁止事后手改数字。

### 4.1 总览（`coverage-summary.json`）

| 字段 | 含义 |
|------|------|
| `unicodeVersion` | 对齐的 Unicode 版本 |
| `fontPostScriptName` | 如 `XiaoheiziMono-Regular` |
| `mapped` | 已映射码位数量（全平面） |
| `assignedInVersion` | 该 Unicode 版本已分配标量值数量（不含代理、非字符） |
| `mappedPercentOfAssigned` | `mapped / assignedInVersion`（说明：字体不必覆盖全部 Unicode） |
| `productCoverage` | 下文 §4.2 分集表的机器可读副本 |
| `widthViolations` | 宽度断言失败的码位列表；发布时必须为空 |
| `sources` | 上游名称与版本 / commit |

### 4.3 分块表（`coverage-blocks.md` 后半）

按 [Unicode Block](https://www.unicode.org/Public/UCD/latest/ucd/Blocks.txt) 一行一块（首发至少输出必测区块）：

| 区块 | 范围 | 该版本已分配 | 已覆盖 | 覆盖率 | 格子（1 / 2 / 混） | 来源 |
|------|------|--------------|--------|--------|-------------------|------|

「混」只允许出现在同一区块内确实混有半角与全角的块（例如半角/全角形式区）。盒绘、基本拉丁不得为「混」。

### 4.4 必测区块

下列区块在首发 Regular 中必须有明确覆盖率（可为 0，但不得缺行），并在验收中人工看一眼：

- Basic Latin `U+0000–007F`
- Box Drawing `U+2500–257F`
- Block Elements `U+2580–259F`
- CJK Unified Ideographs `U+4E00–9FFF`
- CJK Symbols and Punctuation `U+3000–303F`
- Halfwidth and Fullwidth Forms `U+FF00–FFEF`

汉字覆盖另附：**通用规范汉字表**（一级 / 二级 / 三级）收录率，便于中文用户阅读，不替代 Unicode 分块表。通用规范汉字表可在后续阶段补入 §4.2，不阻塞 Regular 首发。

## 5. 验收（P3）

1. 覆盖表已生成，`widthViolations` 为空。
2. 预览串中竖线对齐（半角盒绘 + 汉字 2 格）。盒绘样例行高 **1.2**（字形上下伸出约 1.26 em，`1.4` 会露出缝）。细线 `┌─┐`、双线 `╔═╗`、粗框细内竖 `┏━┯┓` / `│` / `┿` 均须用本字体，不得缺字回落到别的等宽字体。

汉字按 **2 格** 数齐列宽。下面这张表列宽 14 格；「名称」占 4 格，两侧各 5 个空格，不能写成 4+7（那会变成 15 格，竖线错位）：

```text

┃      ID      │     名称     │     类型     │     状态     ┃
┣━━━━━━━━━━━━━━┿━━━━━━━━━━━━━━┿━━━━━━━━━━━━━━┿━━━━━━━━━━━━━━┫
┃     3001     │   监控服务   │     支持     │    运行中    ┃
┗━━━━━━━━━━━━━━┷━━━━━━━━━━━━━━┷━━━━━━━━━━━━━━┷━━━━━━━━━━━━━━┛
```

细线样例：


3. 抽查：`A` 与 `中` 的 advance 比为 1:2；`─`（U+2500）与 `A` 同宽。
4. `font-family` 主名为 `Xiaoheizi Mono` / 小黑字等宽，不含上游保留名。

## 6. 配套表情字体

Regular **不收录**彩色 emoji，以免本体膨胀、也不把 ✅ 等 BMP 符号改成彩图。另出 **两套** 配套字体，格子相同，画风不同：

| 名称 | CSS 族名 | 上游 |
|------|----------|------|
| 小黑字表情 | `Xiaoheizi Emoji` | [Noto Emoji](https://github.com/googlefonts/noto-emoji) COLRv1 |
| 小黑字表情微软 | `Xiaoheizi Emoji MS` | [Fluent UI Emoji](https://github.com/microsoft/fluentui-emoji) Color 画风（官方仓为 SVG；构建取已合成的 Color TTF 再调度量） |

| 项 | 约定 |
|----|------|
| 格子 | 一枚 emoji 推进宽度 **1 em = 2 格**，与汉字同宽 |
| 用法 | `font-family: "Xiaoheizi Mono", "Xiaoheizi Emoji"` 或把第二项换成 `"Xiaoheizi Emoji MS"`；等宽本体优先 |
| 许可 | Noto 衍生：SIL OFL 1.1，不得使用保留名 `Noto`。Fluent 画作：MIT（微软），须保留 MIT 声明；族名不得使用 Fluent / Microsoft 商标 |

构建产物：`dist/XiaoheiziEmoji-Regular.ttf`、`dist/XiaoheiziEmojiMS-Regular.ttf`。预览页加载 `preview-emoji.ttf` 与 `preview-emoji-ms.ttf` 做对照。

## 7. 自动发布（GitHub Actions）

工作流文件：`.github/workflows/publish.yml`。推送到 `main`（或手动 `workflow_dispatch`）时依次：

1. 下载 `vendor/` 上游（不入库），构建 Regular 与两套表情字体。
2. **GitHub Pages**：把预览子集（`index.html`、`preview*.ttf`、`coverage.js`）发布到 Pages。仓库须在 Settings → Pages → Source 选 **GitHub Actions**。完整 TTF 不进 Pages。
3. **打 tag + Release**：在当前 `main` 提交上打 `v0.1.0-preview.<run_number>`，并创建 GitHub Release。附件为完整 TTF、OFL/MIT 与覆盖表。提交说明含 `[skip release]` 时跳过本步。Fork 不发 Release。

禁止手抄覆盖数字进 Release；数字必须来自同一次构建的 `coverage-*.` 文件。完整 TTF 只进 Release，不进 Pages。
